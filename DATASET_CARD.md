# DocFieldBench dataset card

*Draft. Filled in from the build's diversity report at v1.0.0.*

## Summary
About 260 documents in three tracks (Business, Records, Forms), each with a JSON schema and gold for every field.
About one field in eight is absent from its document by design.

## Composition
Counts by track, source, layout family, language, input format, pages, schema size, field type, absent rate and
field tags: generated by the build.

## Construction
- **Gold provenance:** source markup (embedded e-invoice XML, inline XBRL, programmatic form fills, official
  metadata) or human labels, recorded per field. No gold value comes from a model.
- **Absent fields:** natural (a schema field the document doesn't give) or added from the same document family's
  schemas, each verified absent by searching the document text.
- **Visibility:** every present value is findable in the text it is scored on.
- **Adjudication:** before release, every field where any system disagreed with gold was reviewed blind; the log
  lists each change and its reason.

## Input
Each task is the original document (PDF, PNG/JPEG or HTML), up to 10 pages. The dataset ships no text, OCR output or
page images: reading the document is part of what is tested. Single-page born-digital documents also come as scan
and photo variants with the same gold (`variant_of`), so the conditions compare on the same documents.

## Limitations
- Documents up to 10 pages; no long-document track yet.
- Rendered business documents are synthetic records in real templates.

## Contamination
- Every file carries the canary string from `docfieldbench/__init__.py`.
- Each document lists its publication date; documents published on or after 2026-11-01 postdate current models'
  training cutoffs, and each release adds new ones.

## Versioning
Releases are immutable (sha256 per file). Gold fixes go into a new version with a changelog entry.
